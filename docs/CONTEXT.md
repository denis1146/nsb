# CONTEXT.md

## 🎯 Project Goal

**Briefly:** Not a simple sandbox (nsb) — it is a sandbox for experimenting with Boost, GoogleTest, custom cache implementations, and other useful features.

**Task:** Provide a structured environment for testing and studying modern C++ libraries and programming patterns.

**End result:** Project build with libraries and executables for running tests and demonstration examples.

## 🏛️ Architectural Overview

**Technology stack:**
- Language: C++23
- Build system: CMake (version 3.31.5+)
- Libraries: Boost 1.88.0, GoogleTest 1.17.0
- Development tools: VS Code, clang-format

**Key entities (based on source code):**
- `StateMachine` (libs/StateMachine): finite state machine implementation
- `Array` (libs/containers): custom container
- `TaskManager` (libs/TaskManager): task management using Boost.Asio
- Numeric algorithms (libs/numeric): utilities for numerical computations
- Cache (libs/caches): implementation of various caching strategies
- Tests (libs/libs_testing): unit tests for all the above components
- Demo code (notes/): collection of examples and experiments (Pimpl, ScopeExit, Ranges, Factory, Boost.Asio, etc.)

**Tools:** VS Code with preconfigured CMake settings (.vscode), generation scripts (gen.sh, gen_clang.sh)

## 🧩 Dependency Context (from CMakeLists.txt)

- **Boost 1.88.0** (required)
  - Found at: `${CMAKE_SOURCE_DIR}/ext_libs/boost_1_88_0`
  - Linked via `nsb_ext_boost` targets
- **GoogleTest 1.17.0** (required)
  - Found at: `${CMAKE_SOURCE_DIR}/ext_libs/gtest_1_17_0`
  - Linked via `nsb_ext_gtest` target
- Common target `nsb_ext_all_libs` combines Boost and GoogleTest

## 🧠 Key Coding Instructions and Rules

**Standard:** C++23

**Formatting:**
- clang-format is used
- Configuration file: `.clang-format`
- Exceptions: `.clang-format-ignore`

**API usage:**
- Boost is used in the `libs/` directory
- GoogleTest is used for unit tests (integrated via CTest)
- Custom libraries in the `libs/` directory should be self-contained and well-documented
- Resource leaks should be avoided; use RAII and smart pointers

**Error handling:**
- In CMake: using `REQUIRED` when searching for packages causes fatal error if not found
- In code: expected use of C++ exceptions or codes (e.g., `boost::system::error_code` in Asio)

**Constraints:**
- CMake version 3.31.5 or higher required
- Boost 1.88.0 (exact version) required
- GoogleTest 1.17.0 (exact version) required
- Strict compilation mode: `-Wall;-Werror;-Wpedantic;-Wextra` (for GCC-like compilers)
- For MSVC: `-W3`
- In development mode: `-Wshadow` is added
